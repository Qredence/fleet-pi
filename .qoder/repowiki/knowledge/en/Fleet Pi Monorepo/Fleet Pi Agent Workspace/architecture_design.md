The workspace is a flat, Markdown-first directory structure declared by `manifest.json`, which enumerates canonical sections (`instructions`, `system`, `memory`, `plans`, `skills`, `evals`, `artifacts`, `pi`), a temporary `scratch/` area, and a projection-only `indexes/` directory backed by `workspace-projection.sqlite`. Policies are centralized under `system/` (identity, behavior, constraints, tool-policy, workspace-policy, self-improvement-policy) and referenced by key in the manifest so the runtime can enforce mutation boundaries. Memory is split into durable project-level docs (`memory/project/`) and research notes (`memory/research/`). Plans follow a lifecycle with `active/`, `completed/`, and `abandoned/` subdirectories plus a `backlog.md`. Skills are self-contained directories each containing a `SKILL.md` entrypoint and optional `changelog.md`/`examples.md`. Runtime resources live under `pi/` (extensions, packages, prompts, skills) while executable bridges remain under `.pi/extensions/`; the root `.pi/settings.json` acts as a compatibility bridge. The top-level `AGENTS.md` and `index.md` serve as the agent-facing navigation map and operating constraints, and `ARCHITECTURE.md` documents the overall design.
