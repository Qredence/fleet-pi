The module is organized into three concentric layers around the PI chat surface:

- `chat-client.ts` exposes a `ChatClient` interface that wraps all `/api/chat/*` HTTP endpoints, using `chat-fetch.ts` for JSON fetching with Zod validation (`fetchValidatedJson`) and SSE-style streaming (`readChatStream`). URL resolution goes through `chat-runtime-url.ts`, which can prefix requests with an external runtime base URL from `VITE_FLEET_PI_CHAT_RUNTIME_URL`.
- `server-runtime.ts` owns the long-lived `AgentSessionRuntime` lifecycle: creation via `createPiRuntime`, reuse/eviction through an in-memory `runtimeRecords` Map keyed by sessionId, TTL-based disposal, and plan-mode integration. It composes `session-factory`, `active-sessions`, `circuit-breaker`, and Daytona sandbox tooling.
- `runtime/` is a sub-package re-exported through `runtime/index.ts` that encapsulates model catalog, resource catalog, provider catalog, project settings persistence/merge/hot-reload, diagnostics, and session service construction — all consumed by both the server runtime and the top-level `server.ts` barrel.
- `server.ts` is the public barrel aggregating exports from `runtime`, `server-runtime`, `server-sessions`, and `server-shared` for downstream consumers (e.g., Next.js API routes).
- Cross-cutting concerns live as flat files at the module root: `chat-fetch.ts` (HTTP + streaming), `circuit-breaker.ts`, `plan-mode.*` (plan/questionnaire state machine), `slash-commands.ts`, `use-chat-*` React hooks, and `server-*.ts` utilities for event encoding, session file management, and shared helpers.
