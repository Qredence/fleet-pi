The module is a flat collection of single-responsibility TypeScript files re-exported through `index.ts`, which serves as the public API surface for the rest of the web app. Internal layering:

- Session lifecycle: `session-factory.ts` builds `AgentSessionServices` via `@earendil-works/pi-coding-agent`, bootstraps workspace health with exponential backoff (`loadBestEffortWorkspaceHealth`), hydrates durable project settings, and registers the OpenAI chat-completions provider.
- Active session registry: `active-sessions.ts` holds a process-global `Map<string, ActiveSessionRecord>` keyed by sessionId, shared across modules for hot-reload targeting.
- Settings pipeline: `durable-project-settings.ts` merges Fleet base settings with per-user/per-project overrides (file on local, DB on Vercel), sanitizes non-portable paths, and applies them to services; `settings-bridge.ts` exposes the high-level `loadChatSettings`/`updateChatSettings`/`saveProjectSettingsOverrides` API used by the chat protocol, wiring in hot-reload and impact calculation.
- Model/resource/provider catalogs: `model-catalog.ts`, `resource-catalog.ts`, `provider-catalog.ts` each create ephemeral sessions to query the underlying agent runtime, normalize responses into `@workspace/pi-protocol/chat-protocol` types, and filter by enabled patterns or BYOK credentials.
- Hot-reload: `hot-reload.ts` iterates `getActiveSessionRecords()` and re-applies merged settings, resource reloads, model selection, and auth for changed runtimes.
- Diagnostics: `diagnostics.ts` aggregates warnings from workspace bootstrap, model runtime, settings manager, resource loader, extension tool allowlist drift, and database mirror health.
  Dependency direction is one-way outward: this module depends on `@earendil-works/pi-coding-agent`, `@workspace/pi-protocol`, and internal `lib/db`, `lib/workspace`, and `lib/env-manager`; it never imports sibling runtime modules except through the explicit cross-file imports shown above.
