The module is organized around three core layers with clear dependency direction:

- **Contract layer** (`workspace-contract.ts`, `workspace-index-types.ts`): Central source of truth for the workspace schema — section names, required directories, policy file definitions, manifest Zod schema, and all enum-like type constants used across the module.
- **FS abstraction layer** (`workspace-fs.ts`): Defines the `WorkspaceFS` interface (stat, access, mkdir, writeFile, readFile, readdir) with two implementations: `createLocalWorkspaceFS()` wrapping Node `fs/promises`, and `createSandboxWorkspaceFS()` that shells out via an `executeCommand` operation for remote sandboxes (Daytona). All other modules depend only on the interface.
- **Bootstrap & server layer** (`bootstrap-agent-workspace.ts`, `server.ts`): `bootstrapAgentWorkspace` walks the workspace root, ensures sections/directories/policies/scratch protection exist, validates the manifest against the Zod schema, initializes the projection database, and returns a rich `WorkspaceHealthResponse`. `server.ts` exposes HTTP-facing functions (`ensureAgentWorkspace`, `loadAgentWorkspaceTree`, `loadAgentWorkspaceFile`) that gate on workspace health, resolve the listing root (preferring nested `agent-workspace/` when the volume root is polluted), enforce path traversal safety, and return `WorkspaceFileResponse` objects.
- **Context resolution** (`workspace-context.ts`): Resolves `AppRuntimeContext` by optionally injecting a Daytona sandbox context based on user credentials; sets `context.workspaceFS` and `context.workspaceRoot` so bootstrap/server code can be environment-agnostic.
- **Semantic parsing layer** (`workspace-semantic-parsers.ts`): `classifyWorkspacePath` maps any canonical path under `agent-workspace/` to a `WorkspacePathClassification` (category, pathType, sourceOfTruth, parserKind), then `parseWorkspaceFile` dispatches to format-specific parsers (manifest-json, json, jsonl, markdown, text) producing `WorkspaceSemanticParseResult` with typed records for indexing.
- **Client shim** (`client.ts`): Thin browser-side fetch wrapper hitting `/api/workspace/file?path=...` and returning `WorkspaceFileResponse`.

Dependency direction is strictly inward: client → server → bootstrap → fs-abstraction → contract/types. Tests mirror each production file (`*.test.ts`, `*.spec.ts`).
