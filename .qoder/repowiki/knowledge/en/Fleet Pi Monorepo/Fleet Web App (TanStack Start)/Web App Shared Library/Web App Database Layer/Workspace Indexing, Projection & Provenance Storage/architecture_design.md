Three cooperating modules share a single SQLite file (`workspace-projection.sqlite`) under `<workspaceRoot>/indexes/` (or `/tmp/agent-workspace/indexes/` on Vercel):

- `workspace-projection.ts` owns the schema: `projects`, `workspace_roots`, `workspace_items`, `workspace_item_versions`, `workspace_semantic_records`, plus a `projection_migrations` table. It provides connection lifecycle (`openWorkspaceProjection`, `initializeWorkspaceProjection`, `seedWorkspaceProjectionConnection`) and read APIs (`listWorkspaceProjectionItems`, `getWorkspaceProjectionItemDetail`, `searchWorkspaceProjection`).
- `workspace-indexer.ts` walks the filesystem, classifies and parses each file via `../workspace/workspace-semantic-parsers`, computes SHA-256 content hashes, builds an idempotent `WorkspaceIndexPlan` (insertions/updates/reactivations/unchanged/deletions), and applies it atomically through `applyWorkspaceIndexPlan` using prepared statements inside a `db.transaction()`.
- `workspace-provenance.ts` extends the same DB with `provenance_sessions`, `provenance_runs`, `provenance_run_events`, `provenance_tool_calls`, `provenance_mutations` tables created by `ensureWorkspaceProvenanceSchema`. It records assistant run lifecycles (`insertRunStart`, `appendRunEvent`, `upsertToolCall`, `replaceRunMutations`, `finalizeRun`) and exposes query helpers (`listSessionRuns`, `getRunDetail`, `listPathProvenance`).

Dependency direction is one-way: indexer depends on projection; provenance depends on projection for the shared connection. All IDs are deterministically derived via `createHash('sha256')` from stable keys, ensuring idempotent upserts across runs.
