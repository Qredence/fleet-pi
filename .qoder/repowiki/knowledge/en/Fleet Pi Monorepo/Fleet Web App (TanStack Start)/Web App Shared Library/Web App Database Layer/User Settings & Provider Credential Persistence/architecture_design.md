Six focused modules under `apps/web/src/lib/db/` each target a single database concern and share two common patterns: (1) all DB writes go through `withChatPostgresTransaction` from `./pi-session-mirror`, which supplies a `PostgresQueryClient` inside a transaction scoped to a `userId`; (2) every module guards against missing configuration by checking `process.env.FLEET_PI_CHAT_DATABASE_URL` via an `isChatDatabaseConfigured()` helper, throwing `ChatPostgresUnavailableError` on Vercel when the env var is absent. `user-settings.ts` reads/writes JSONB in `pi_user_settings`. `user-providers.ts` stores encrypted API keys or OAuth payloads in `pi_user_providers`, using `encryptString`/`decryptString` from `../auth/crypto` with `BETTER_AUTH_SECRET`. `remove-provider-with-settings.ts` atomically deletes provider rows and optionally upserts settings in one transaction. `session-ownership.ts` is pure logic that classifies a row into `owned | foreign | missing | orphan | deleted` and decides access. `remap-auth-user-ids.ts` parses CSV-style email-to-user-id mappings used during migration. `auth-postgres-post-migrate.ts` exports a SQL string that conditionally drops legacy Better Auth tables when Neon Managed Auth is present, or enables RLS and grants `fleet_pi_app` when it is not.
