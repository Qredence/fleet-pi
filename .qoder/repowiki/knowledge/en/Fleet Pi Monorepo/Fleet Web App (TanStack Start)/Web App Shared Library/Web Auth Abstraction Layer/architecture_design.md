The module is organized around a runtime-selected backend strategy driven by `auth-mode.ts`, which resolves `AuthBackend` (`local-better-auth` | `neon-managed`) from `NEON_AUTH_BASE_URL`/`VITE_NEON_AUTH_URL`. Both `server.ts` and `client.ts` are thin adapters: they import the chosen backend lazily via dynamic `import()` so the opposite implementation is never loaded in a given process. `server.ts` exposes `{ api.getSession, handler }` and `client.ts` exposes an `authClient` singleton plus `getChatAuthBearerToken()` with in-memory caching and concurrent-request coalescing. Cross-cutting concerns (AES-GCM encryption, CSRF token handling, JWT verification against JWKS, host/origin policy) live in `shared_utils` and are consumed uniformly by both backends. Tests under `__tests__/` cover the mode boundary, each backend, and the chat auth surface to ensure the abstraction stays stable for consumers.
