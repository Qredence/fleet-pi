Five focused, single-responsibility modules under `apps/web/src/lib/auth/` with no internal dependencies between them except `jwt-verify.ts` importing from `auth-mode.ts`. `crypto.ts` exposes pure `encryptString`/`decryptString` using Node's `node:crypto` (AES-256-GCM with scrypt key derivation) and a `salt:iv:tag:data` wire format. `csrf.ts` implements stateless CSRF protection by issuing tokens into an HttpOnly cookie and validating against a matching header using `timingSafeEqual`. `jwt-verify.ts` uses the `jose` library to verify Neon Managed Access Tokens against a remote JWKS endpoint cached in module-level variables, delegating issuer/base-url resolution to `auth-mode.ts`. `auth-host-policy.ts` defines static allowlists (`VERCEL_AUTH_HOSTS`, `LOCAL_TRUSTED_ORIGINS`) and helper functions to compute trusted origins per deployment context. `auth-mode.ts` centralizes environment-driven configuration resolution (`NEON_AUTH_BASE_URL`, `BETTER_AUTH_SECRET`, Vite env vars) and determines whether the backend is local Better Auth or Neon Managed Auth. Dependency direction is one-way: `jwt-verify.ts` → `auth-mode.ts`; all other files are independent utilities consumed by higher-level auth handlers.
