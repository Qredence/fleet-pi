The module is a thin barrel (`deployment.ts` re-exports `./deployment/index`) over four focused files under `src/lib/deployment/`. `environment.ts` provides the single client-safe `isVercelDeployment()` helper (no Node-only imports). `trust-zone.ts` resolves the deployment trust zone (`local` | `vercel-production` | `vercel-preview`) from `VERCEL_ENV` and exposes `shouldFailClosedOnMirrorError` / `requiresAuthenticatedMirrorOwner` for fail-closed mirror behavior. `readiness.ts` implements `validateDeploymentReadiness`, which runs a suite of named checks against env vars, Neon Managed Auth settings, preview-vs-production database markers, RLS state, migration IDs, and embedded SQL artifacts. `boot-check.ts` wires these together: `assertDeploymentReadyOnBoot` short-circuits outside Vercel serverless runtimes and throws on any failed readiness check; `formatReadinessFailure` formats the check results. Tests live in `__tests__/` alongside each source file. Dependency direction is one-way: `boot-check` → `readiness` + `trust-zone` → `environment`; `readiness` depends only on `trust-zone` and static migration constants from `../db/*`.
