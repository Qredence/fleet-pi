Each route is a TanStack Router `createFileRoute` declaration colocated in a single file under `routes/api/workspace/` (and `chat.ts` at the api root). Every handler follows the same shape: wrap the request with `withAuthenticatedChatRequest` from `@/lib/auth/chat-api-auth`, resolve a workspace context via `resolveWorkspaceContext(request, authSession?.user)`, then delegate to a domain function in `@/lib/workspace/*` (`workspace-query`, `server`, or `bootstrap-agent-workspace`). Error handling is uniform — known domain errors like `WorkspaceQueryApiError` are returned as-is, while unexpected errors are wrapped via `createUnexpectedWorkspaceQueryErrorResponse` or mapped through `getResponseStatus`/`getErrorMessage`. The `/api/workspace/reindex` route is the only one using both GET (CSRF token issuance) and POST (rate-limited reindex), with an in-process sliding-window rate limiter keyed by `userId` or origin. Dependency direction is strictly inward: routes depend on `@/lib/auth`, `@/lib/workspace`, and `@/lib/pi/server`; no cross-imports between sibling route files.
