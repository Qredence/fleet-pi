Two sibling route directories under `@/routes/api/` each declare TanStack Router file-based routes via `createFileRoute`. The `sandbox/` directory exposes two GET/POST endpoints: `/api/sandbox/preview` (auth-gated, validates port, resolves a user's cached Daytona sandbox handle, and returns a preview link) and `/api/sandbox/settings` (GET reads env-var configuration with CSRF token issuance, POST updates `DAYTONA_API_KEY` / `DAYTONA_TARGET` via `updateEnvVar` after CSRF validation). The `webhooks/` directory exposes `/api/webhooks/daytona` which accepts signed POST webhooks from Daytona, verifies the `x-daytona-signature` header against `DAYTONA_WEBHOOK_SECRET` using `timingSafeEqual`, and clears the in-memory user-sandbox cache on error events. All handlers depend only on shared libraries (`@/lib/auth/server`, `@/lib/daytona/user-sandbox`, `@/lib/env-manager`, `@/lib/pi/server`) and never import each other, keeping the two sub-routes independent. A Vitest test file (`-daytona.test.ts`) mocks the day-to-dayta cache module to verify signature verification and cache-clearing behavior.
