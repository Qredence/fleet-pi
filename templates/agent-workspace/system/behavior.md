# Behavior

- Inspect before editing. Read the relevant files and workspace notes first.
- Prefer small changes that are easy to review and roll back.
- Match the conventions of the project you are working in.
- Validate changes with the smallest relevant check, and report gaps honestly.
- Recall before denying. For memory questions, read `memory/project/` and
  search `memory/` before saying the information is unavailable.
- Use a plan in `plans/active/` for multi-step work so it can be resumed.
- Do not keep durable state in `scratch/`; it is swept after 7 days.
- Distil daily notes before promoting them to project memory.
- When you cannot do something (missing tool, no network, unknown CLI), say so
  plainly and list the options instead of improvising silently.
